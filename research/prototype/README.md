# 臺中頁面原型

線上版：https://claude.ai/code/artifact/8db1ddf5-d5a5-4c3e-8d1c-697389690695

目的不是做一個好看的頁面，而是驗證 `build/` 的資料層撐不撐得起真正的頁面。結論是撐得起：年齡軸、機構、關係、動態四張表在同一頁上接得起來，沒有靠任何臨時湊的資料。

`taichung.html` 是產生物（約 300KB，資料直接內嵌），不進版控；進版控的是 `taichung.template.html` 與 `build_page.py`。

要更新已經發布的頁面，就用同一個檔案路徑重新發布，網址不變。

## 首頁的規劃

一屏只回答一條問題鏈，而且**主從分明**：孩子幾個月大 →（時間軸）到哪一站 → **現在該做什麼**（主角）→ 去哪裡。

之前失敗的版本是把資料表的分類原封不動搬上畫面：發展篩檢、預防保健、線上檢核表、分齡量表、家長紀錄各佔一行。但這五項對家長是同一件事——「這個年齡的發展檢查」。四個區塊平鋪、每個都要空間，於是每個都不夠，怎麼調 CSS 都會擠。

現在的版面：主角是一句結論（「第 4 次兒童發展篩檢，2 歲至 3 歲做」）＋一個主要行動（先自己填檢核表）＋一行次要；機構從 10 家收成 2 家加總數；預防保健 9 格、趨勢圖、五個步驟籤、上百筆清單全部移出首頁。

空間預算（實測）：固定列 387px（頂列 50＋時間軸 63＋下方卡片 167＋footer 27＋間距 48＋內距 32），主角需要 214px。所以 **650px 以上的容器主角完整顯示**，520px 這種極矮容器會差 81px，主角在自己的框內捲動。

## 內頁

首頁只回答一條問題鏈，其餘全部移到內頁，入口在 footer（做成獨立一列會再吃掉 30px 版面高度）。同一個檔案、用 hash 路由切換，所以發布網址不變、資料也只載入一次。

| 路徑 | 內容 | 為什麼要有 |
|---|---|---|
| `#/checkups` | 發展篩檢 6 次、預防保健 9 次、分齡量表 9 份畫成三排格子，當前月齡那格亮起；家長自填的項目只列當下這一層 | 首頁只放得下「這一次」，但家長會想看整條軸長什麼樣。兩套檢查次數不同、很容易混，並排才看得出差別 |
| `#/steps` | 篩檢→通報→評估→療育→學前教育五步，各步的家數；另附「家長說法 ↔ 官方分類」對照表 | 官方分類名稱看不懂是真的障礙，這張表就是翻譯 |
| `#/places` | 全部 555 家，可依行政區與類型篩選；有動態資訊的機構會附上門診時間、預約方式或分機 | 首頁只放 2 家。這裡也標出哪些機構的座標只到行政區。動態資訊若只存在資料層、頁面上沒有出口，等於沒解析 |

動態資訊的來源已涵蓋全國：國健署的全國聯絡資訊（22 縣市 51 家）打底，再疊上縣市特有的欄位——嘉義市的門診時間、臺中標了初評／複評的分機、新北的預約方式。頁面顯示前會去重：`entity` 存「(04)3604-5483」、衛生局頁存「04-36045483」，比字串比不出來要比數字，而「分機」這兩個字本身不算資訊，不先拿掉的話同一支電話會顯示兩次。
| `#/map` | 各行政區的機構家數畫成圓圈，點一下跳到那一區的清單 | 「哪一區有幾家」是家長第一個想知道的空間問題 |
| `#/subsidy` | 該縣市的補助上限、項目、申請期限與出處連結 | 補助是家長第二關心的事，但規則 22 套各不相同，只能逐縣市列 |
| `#/materials` | 檢核表 13 層的題數與警訊題數、量表、宣導與繪本 | 這些素材原本散在四個機關的網站 |

內頁吃的是同一份 `DATA` 與同一個月齡，所以從首頁點進去看到的內容會跟著滑桿走，不是靜態清單。

**分布圖為什麼沒有底圖、也只畫到行政區**：artifact 的 CSP 只允許少數幾個 CDN 的 script，圖磚是 image 請求，一律擋掉且不會報錯——硬放底圖只會得到一片空白。所以直接把經緯度投影成 SVG（經度乘 `cos(緯度)` 才不會橫向拉寬）。至於為什麼不畫每一家機構的點：3,073 家裡只有 1,378 家是門牌座標，其餘是區中心點，混在一起畫會讓整區的機構疊成一個點，看起來像「這區只有一家」。

素材清單的形狀不一致，三種都要接：國健署量表是**純字串陣列**、宣導與繪本是物件，而物件的連結有的是絕對網址、有的是相對路徑（社家署寫 `/cecm/...`）。相對路徑直接放進 `href` 會連到頁面自己的網域，變成壞連結。

## 手機版與邊界踩過的六個坑

手機不是「把兩欄併成一欄」就好，要單獨設計：390px 寬放不下橫排的控制列與 6 格時間軸。

1. **橫向溢出**：`white-space: nowrap` 的電話配上長機構名、固定寬度的日期輸入框與滑桿，會把整列撐破畫面，右半邊內容直接被切掉。手機版要讓這些改為可換行，並加上 `overflow-x: hidden` 當最後一道防線。
2. **class 撞名**：時間軸當前站原本叫 `.stop.now`，而主角卡片的 class 正好是 `.now`——卡片的白底、邊框、內距整套套到那一站上，畫面多出一個莫名其妙的方框。已改名為 `.stop.current`。
3. **用 CSS 隱藏鄰居會讓資訊張冠李戴**：名額開放日原本獨立放在清單末尾，手機版隱藏第 2 家之後，畫面變成「列的是甲醫院、名額寫乙醫院」。修法是把名額和它所屬的機構包成同一個 `.item`，要藏就整組藏。
4. **`scrollHeight` 等於視窗高度不代表內容溢出**：`height:auto` 的 `html` 至少會填滿 viewport，所以 390×844 量到 `scrollHeight = 844` 時，內容其實只有 568px。要看實際內容高度得量 `.app` 或最後一個子元素的底部，否則會誤判成「還要捲 240px」而繼續瞎砍。
5. **滑桿的最大值正好是所有資料的上界，拉到底必然全空**：月齡滑桿 `max=84`，而 timeline 每一類的 `month_max` 也都是 84，判斷式又是左閉右開（`age >= min && age < max`）——所以 `age=83` 命中 5 筆、`age=84` 命中 0 筆。84 是滑桿上唯一一個所有資料都落空的值，而它正好是拉到底的位置，使用者一拉到最右邊就必然看到空白。這不是排版壞掉，是邊界沒想清楚。

   處理方式不是把滑桿改成 83（那樣「7 歲」這個真實的轉銜時點就消失了），而是讓滿 7 歲那一格有實質內容：六次篩檢的年齡區間回顧（漏做的不會自動補），加上一段從 `DATA.stats` 現算的事實——**「發展遲緩」在特教統計裡，學前四個年段合計 25,413 人，國小一年級之後是 0**。那不是人不見了，是這個類別只用在學前，入學後要改判其他障別才能繼續拿到特教資源。這是滿 7 歲的家長最該知道的一件事，而且資料自己就講得出來，不必另外找來源。

6. **`matchMedia` 只判斷一次等於沒判斷**：月齡單位會依寬度在「27 個月大」與「27 個月大（2 歲 3 個月）」之間切換，但那是在 `setAge()` 裡讀 `matchMedia` 決定的。沒有監聽 `change` 的話，**手機轉向或縮放視窗跨過 860px 時不會重畫**，長版留在 390px 上會把控制列撐到 440px。修法是 `NARROW.addEventListener('change', () => setAge(age))`。

   這個坑之所以躲過前幾輪量測，是因為每次都先 `navigate` 再量——重新載入時尺寸已經正確，永遠測不到「載入後才改變尺寸」這條路徑。**要驗響應式，就得在不重載的情況下 resize 再量。**

## 版面的四個決定

1. **視覺取自兒童健康手冊**：家長人手一本，裡面就是表格、虛線格、要蓋章的「就醫憑證」。所以預防保健 9 次與發展篩檢 6 次畫成兩排格子，當前月齡落在哪格就亮起來。這是這個題目特有的文件慣例，不是裝飾。
2. **入口是月齡，不是地區**：0–6 歲該做什麼全綁在年齡上，先問幾個月大，才問住哪裡。
3. **通報轉介中心放在機構清單前面**：家長最常卡在「不知道從哪開始」，而這正是通報轉介中心的職責。這也落實 v0 §5 第 4 條：站是路標，不是窗口。
4. **首頁是一屏，靠內容量成立，不靠縮放**：頁面本身不捲動，`.app` 是 `height: 100%` 的 grid，五列分別是控制列、時間軸、主角、機構、footer。

   **`1fr` 給機構清單那一列，不給主角卡片**。一開始是相反的，結果主角吃掉所有剩餘空間，而它的內容量隨月齡差很多——滿 7 歲時只剩三行字，底下就是 151px 的空白（0 個月大也只有 108px 的內容）。改成主角高度隨內容、剩餘空間給清單之後，主角的留白降到 15–28px，而清單反過來吸收了高度（0 個月大時 327px、84 個月大時 211px），清單本來就有上百筆，捲動才合理。配套是 `.go` 要 `min-height: 0` 才讓得出高度給 `#places` 內部捲動，左邊的求助電話卡 `align-self: start` 才不會被拉長。

   實測四個月齡（0／27／60／84）在 1200×650 都是 `appH = 650`、不溢出、主角不需要內部捲動。

   先前試過「等比縮放的一屏」——字級綁 `clamp(10px, calc(0.6vw + 0.6vh), 16px)`、其餘尺寸全用 `em`／`%`／`fr`，讓視窗變矮時整體縮小。放棄的原因是它治標：內容太多時只是把字縮到看不清楚，而且係數稍小就會在一般筆電尺寸觸到 clamp 下限、退化成固定字級。真正的解法是把內容砍到一屏放得下（預防保健 9 格、趨勢圖、五步驟、上百筆清單全部移到內頁），砍完之後固定 15px 就成立。視窗窄於 860px 降級成單欄捲動版。

   **最大的坑是 `dvh`／`vh`**：artifact 是嵌在容器裡渲染的，`dvh`／`vh` 抓的是外層視窗高度。容器只要比外層矮，`body` 就會比容器高，而 `overflow:hidden` 會把底部整塊切掉——footer 和通報轉介中心直接消失。所以高度一律用 `html, body { height: 100% }` 跟隨實際容器，區塊高度用 `em`，字級只綁 `vw` 不綁 `vh`。

   另外兩個坑：係數太小（0.40vw+0.42vh）會在一般筆電尺寸就觸到 clamp 下限，等於退化成固定字級；區塊內部若用 `rem`，父層的 `em` 降級會被擋住縮不下去，要用 `em` 才會整塊等比。

   驗收不要只看截圖——截圖在同一個瀏覽器分頁換尺寸時不一定生效，要直接量：

   ```js
   document.documentElement.scrollHeight > document.documentElement.clientHeight  // 必須 false
   getComputedStyle(document.documentElement).fontSize                            // 不該卡在下限
   todo.scrollHeight <= todo.clientHeight                                         // 該做的事要完整顯示
   ```

   實測（首頁與五個內頁各量一次）：

   - 桌機 1200×650：首頁 `scrollHeight` 與 `clientHeight` 都是 650、不溢出，主角完整顯示，機構清單維持表格排版。
   - 手機 390×844：首頁與五個內頁都沒有橫向溢出（`scrollWidth` 皆 390）。

   量測時有個陷阱會讓結果整個作廢：**`navigate` 帶的 width／height 在既有分頁上不生效**，量出來還是上一次的尺寸。要先關掉瀏覽器再開，或明確呼叫 resize，並且每次都把 `clientWidth` 一起印出來確認真的換了——否則會拿桌機的數字當手機的結果回報。

## 已知限制

- **行政區篩選會讓清單變很短**：例如西屯區的「評估」只有 2 家、全市有 16 家。所以預設是看全市，選了行政區才縮範圍，並標明「某區 N 家，全市共 M 家」與「改看全市」。這反映的是真實分布，不是資料缺漏。
- **動態資訊只有 4 筆**（全部來自中山醫附醫）。選了沒有動態資料的行政區就看不到，得切回全市。
- **`serves_area` 沒有拿來當篩選條件**：臺中的療育單位普遍把 29 個行政區全部列為服務區域，每區聚合出來的數字幾乎一樣，對家長沒有鑑別度。頁面只用「實際位於該區」。
- **座標分兩種精度**：門牌座標只有就醫地圖那批有，其餘是行政區中心點（`geo_level=district`）。做地圖時兩者不能混畫——區級座標會讓同一區的機構全部疊在一個點上，看起來像「這區只有一家」。
- **分類名稱已有家長版**：`plain_cat` 欄位（「療育-醫療單位」→「在醫院做治療」），頁面上顯示這個。但頁面其他文案仍沿用官方用語（綜合報告書、通報轉介），還沒逐句改寫。
- **只有臺中發布成線上版**：模板已經參數化，其餘 21 縣市隨時可以產，但還沒決定要不要一個縣市一個網址。
- **手機曾經看到的比桌機少**：為了省空間把時間軸與「同一時期還有」整個藏掉，實測才發現 390×844 的內容只到 557px、底下空了 287px——省下來的空間根本沒人用。放回來之後留白剩 67px，仍然不溢出。**先量再砍**，不要憑感覺省空間。
