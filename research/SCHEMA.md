# 資料格式

`research/build/` 的輸出。資料層用 CSV（機器讀、git diff 可讀），行數 ≤1500 的表另外匯一份同名 `.md` 方便直接在 repo 翻。產生方式見 [`scripts/README.md`](scripts/README.md)。

| 檔案 | 列數 | 一列代表 |
|---|---|---|
| `entity.csv` | 3,073 | 一家機構（跨來源合併） |
| `entity_raw.csv` | 3,835 | 某個來源說的某家機構（保真） |
| `observation.csv` `.md` | 134 | 某時間點在某機構觀察到的一個值 |
| `relation.csv` | 16,169 | 一組關係（超過 1500 列，不匯 md） |
| `stats.csv` `.md` | 690 | 一個統計數值 |
| `district.csv` | 369 | 一個行政區的中心點座標 |
| `rename_candidates.csv` | 0 | 一組疑似更名（舊 key → 新 key），要人工確認 |
| `materials.json` `.md` | — | 教育素材清單 |
| `manifest.json` | 112 | 一個原始檔的指紋 |

## entity.csv

| 欄位 | 說明 |
|---|---|
| `entity_key` | 有健保醫事機構代碼就用代碼（1,177 家）；社福單位退回 `x:<縣市>:<正規化名稱>`。**這個 key 不穩定**，見下方「社福單位沒有穩定 ID」 |
| `name` | 機構全銜，取來源優先序第一個 |
| `plain_cat` | `cat` 的家長版說法，例如「療育-醫療單位」→「在醫院做治療」。頁面上顯示這個，`cat` 留給比對與追來源 |
| `cat` | **主分類**，一家機構身兼多職時取優先序最前者 |
| `cats` | 全部分類，分號分隔，例如 `聯合評估中心;兒童發展篩檢院所;新生兒聽力確診醫院;療育-醫療單位` |
| `journey_step` | 家長旅程的第幾步：1 篩檢／2 通報／3 評估／4 療育／5 學前教育 |
| `county` `district` `address` `tel` | 地址已去掉開頭郵遞區號。`district` **已全數補齊**：來源只有就醫地圖那 1,378 家有，其餘 1,695 家從地址開頭抽出（實測全中） |
| `url` | 機構自己的網站（68 家）。**動態層唯一的入口**，但覆蓋率很低——社家署名錄多數沒填，聯合評估中心只有 9/90 家有 |
| `hosp_id` | 健保醫事機構代碼 |
| `tier` | `重點`／`一般`，**只有國健署名單有**（89 家） |
| `lat` `lng` | WGS84。**每家都有值，但精度分兩種**，一律搭配 `geo_level` 使用 |
| `geo_level` | `address`＝門牌精度（1,378 家，來自就醫地圖）；`district`＝只是所在行政區的中心點（1,695 家）。**頁面上不能混為一談**：區級座標可以畫分布、不能拿來導航 |
| `sources` | 這家機構出現在哪些來源，例如 `hpa;healthforkids;sfaa` |
| `source_updated` | 社家署那筆的更新日期（民國年） |

**社福單位沒有穩定 ID**：1,896 家社福單位的來源（社家署資源查詢）不給任何識別碼——每一筆就是一個 panel，沒有 detail 頁、沒有 id 參數、沒有序號，所以 `entity_key` 只能用「縣市＋正規化名稱」組。機構一改名，下一次 build 就會當成「舊的消失、新的出現」，而名錄類來源的健康檢查規則正是「消失即警示」。補救不是去猜一個 ID，是留住上一版再比對，見 `rename_candidates.csv`。

**逐筆地理編碼走不通**：實測 Nominatim 對臺灣的完整地址與街道查詢一律回空陣列（只有行政區層級查得到），所以沒有座標的那 1,695 家只能退到區級中心點。

合併規則：欄位衝突時取 `hpa` > `healthforkids` > `sfaa`。理由是國健署是聯評中心的官方定義、就醫地圖有座標、社家署則是服務時間與服務區域的唯一來源。

主分類優先序：聯合評估中心 → 評估醫院 → 其他經許可辦理評估之醫院 → 兒童發展篩檢院所 → 新生兒聽力確診醫院 → 新生兒聽力篩檢院所 → 療育-醫療單位 → 早療機構 → 社區療育據點 → 通報轉介中心 → 個案管理中心 → 療育-教育單位 → 服務-教育單位 → 其他社福單位。

**所以 `cat` 的分類統計不等於各來源的原始筆數**：就醫地圖有 1,393 家篩檢院所，但其中 132 家同時是聯評中心或評估醫院，在 `entity.csv` 會歸到那些分類，`cat=兒童發展篩檢院所` 只剩 1,261 家。要按「有沒有提供某服務」篩選，請用 `cats` 欄位而不是 `cat`。

## entity_raw.csv

欄位是各來源的原始欄位：`entity_key, source, cat, county, district, name, 地址, 電話, hosp_id, tier, match, lat, lng, 服務區域, 服務方式, 服務內容, 辦理單位, 更新日期, note`。

- `match` 是怎麼對上代碼的：`name`／`addr`／`addr+hosp`／`substr`／`alias`／`none`／`skip`（社福單位一律不比對，同址常是別的機構）。
- `alias` 表示靠人工對照表補上的，目前兩筆更名案例在 [`scripts/aliases.json`](scripts/aliases.json)：陽明大學→陽明交通大學、臺大新竹分院→新竹臺大分院新竹醫院。
- **彰基刻意不合併**：彰化基督教醫院（1137010024）與彰化基督教兒童醫院（1137010042）在健保名冊是兩個機構、地址不同，聯評中心設在兒童醫院，社家署則把聯評身分掛在本院。合併會抹掉一個真實機構，所以保留兩筆——這也是 `entity.csv` 的聯合評估中心會比國健署 89 家多 1 家的原因。
- **同一個 `entity_key` 會有多列，而且可能同一個 `cat` 也重複**：來源本身就重複登錄。例如中山醫附醫在社家署有 5 筆，其中兩筆都是「聯合評估中心」但電話與更新日期不同。要追「某來源當時怎麼寫的」就查這張表。

## observation.csv

| 欄位 | 說明 |
|---|---|
| `entity_key` | 可 join `entity.csv`；配不到醫事機構代碼時退回 `x:<縣市>:<正規化名稱>` |
| `observed_at` | 觀察時間，取原始檔的抓取時間 |
| `source` | 哪個來源：`csh_quota`（中山醫附醫）／`ntpc_booking`（新北衛生局）／`tc_health`（臺中衛生局）／`cy_health`（嘉義市衛生局） |
| `field` | `quota_release_date`（放名額日）／`monthly_capacity`（每月名額）／`booking_method`（預約方式）／`booking_tel`（電話與分機）／`clinic_hours`（門診時間） |
| `value` | 值。日期已轉成西元 `YYYY-MM-DD` |
| `note` | 原文脈絡，例如「115年10月份門診名額開放日」，或該筆的機構原名 |

**這張表短是現況，不是解析失敗**：13 家聯評中心抽查只有 1 家公布放名額日，**等候天數沒有任何公開來源**——不只各中心不公布，連縣市衛生局的彙整頁也只有聯絡方式。

四個縣市彙整頁的資訊密度差很多：新北只有預約方式、臺中只有電話與分機（但標了哪支是初評哪支是複評）、**嘉義市是目前唯一有門診時間的**。所以 `field` 要看來源，不能假設每家都有同樣的欄位。

## relation.csv

`from_key, rel, to, to_key`。四種關係，同一組三元組已去重：

| `rel` | 列數 | 意義 |
|---|---|---|
| `in_county` | 3,073 | 機構所在縣市 |
| `in_district` | 3,073 | 機構所在行政區（`district` 補齊後每家都有） |
| `serves_area` | 9,959 | **服務區域**，來自社家署欄位。必須當關係而不是屬性，因為通報轉介中心寫「全新北市」、有些療育單位收外縣市，只用地址縣市會漏 |
| `operated_by` | 64 | 辦理單位（例如社區據點由某醫院或基金會承辦）。`to_key` 是承辦單位的 entity_key，配不到就留空 |

|---|---|---|---|---|

## timeline.csv / timeline.md

年齡時間軸——幾個月大該做什麼。站的骨幹之一（另一半是地圖）。

`kind, journey_step, age_label, month_min, month_max, title, detail, source, url`，依 `month_min` 排序。

| `kind` | 筆數 | 內容 |
|---|---|---|
| 兒童預防保健 | 9 | 出生後2週至2個月 … 5歲至未滿7歲，健保給付含衛教指導 |
| 兒童發展篩檢 | 6 | 6至10個月、10個月至1歲半、1歲半至2歲、2至3歲、3至5歲、5歲至未滿7歲 |
| 家長紀錄事項 | 9 | 兒童健康手冊裡家長自填的九個時段 |
| 分齡篩檢量表 | 9 | 6-9個月 … 5-7歲，醫師篩檢實際使用的工具 |
| 線上發展檢核表 | 13 | 社家署 4個月～6歲，`detail` 標了題數與警訊題數 |
| 學前特教安置 | 4 | 幼幼班～大班 |

**兒童預防保健 9 次與兒童發展篩檢 6 次是兩套不同的東西**，都印在兒童健康手冊上、都用「就醫憑證」的形式，很容易混為一談。

月齡以月為單位，可能出現 `.5`：`0.5` 是出生後兩週，`84` 是未滿 7 歲。線上檢核表的區間原文寫成「3個月16天~5個月15天」，換算成 `3.5`–`5.5`——截成整數會讓相鄰兩層在邊界那個月重疊，查「5 個月大」會同時命中兩層。

學前特教安置的年齡是依學制推算的（來源只有班別沒有年齡），其餘都照原文。

## district.csv

`county, district, lat, lng, source`，369 列。行政區中心點，用途有兩個：補機構的區級座標，以及當行政區頁自己的座標。

圖資是 g0v/twgeojson 的鄉鎮界（377 個面），縣市改制前的版本，所以有三個坑：縣市名要換（桃園縣→桃園市、台中市→臺中市…）；比對要同時試原名與去掉「區鄉鎮市」尾字的寫法，因為來源端三種寫法都有（平鎮市／平鎮區／平鎮），**只去尾字會把「平鎮」削成「平」而對不到**；那瑪夏區在這份圖資裡沒有對應的面（改制前是高雄縣三民鄉，與舊高雄市三民區同名，不能猜是哪一個），單獨補一筆 Nominatim 查到的座標，`source` 欄位標成 `nominatim` 而不是 `twgeojson`。

海域面（`TOWNNAME` 結尾是 `(海)`）已排除，中心點會落在海上。機構用到的 359 個行政區目前全部對得到。

## rename_candidates.csv

`county, old_key, old_name, new_key, new_name, evidence, address, tel, sources`。

社福單位沒有穩定 ID，更名只能靠「上一版長什麼樣」比對出來。指紋是 `(縣市, 正規化地址, 電話)`——地址與電話比名稱穩定得多；兩者都有才算數，只有其中一個太容易誤配（同一棟樓、總機共用）。指紋相同但 `entity_key` 變了，就是更名候選。同址同電話有兩家以上時不猜，留給人看。

**輸出只是候選，不自動合併**：`aliases.json` 的規矩是「每筆都要寫證據，不要憑印象合併」，自動合併會讓這條規矩失效。完整流程是：

1. `renames.py` 比對出候選，寫進 `build/rename_candidates.csv`（欄位 `evidence` 記下指紋相同的地址與電話）。
2. 人工確認是同一家——查健保名冊的醫事機構代碼、對地址、必要時打電話。這一步不能省：同一棟樓換承辦單位、機構搬走後原址進駐另一家，指紋都會相同。
3. 確認後寫進 `scripts/aliases.json` 的 `hosp_id_alias`，`reason` 欄位要寫清楚證據。
4. 若確認是**兩家不同機構**（例如彰基本院與彰基兒童醫院），寫進 `known_not_merged` 並說明為什麼不合併，避免下次又被當成候選重看一遍。

比對基準是 `research/entity_prev.csv`（進版控）。第一次跑沒有基準，只會建立快照並印出說明——那時候的「0 筆更名」不是檢查過的結論。

## scripts/subsidies.json

22 縣市早療費用補助規則，人工維護的 override 檔，不做自動解析（每個縣市的計畫是 PDF 或 ASP 頁面，格式各不相同，金額改動要有人看過才算數）。

**`monthly_max` 是「療育費與交通費合計」的上限，但不是每個縣市都這樣算**：高雄的合併上限低於它自己的療育訓練費上限；臺南分成「一般療育」與「簽約機構時段療育」兩套；桃園另有 7–18 歲級距；金門的交通費是臺金機票實報實銷、與療育費分開計。所以除了金額，規則的形狀也要照抄。

`status` 欄位：`verified` 19 個縣市（已讀過官方原文）、`pending` 3 個（苗栗、澎湖、連江——官方頁面查得到計畫名稱，但金額沒有放在任何可解析的頁面上，見該筆的 `note`）。呈現時一律附 `source_url` 與 `verified_at`，不要只顯示數字。

## manifest.json

`{generated_at, files:[{file, bytes, sha256, fetched_at}]}`，`file` 相對 `work/`。

## state.json（排程狀態）

放在 `research/state.json`，**刻意不放進 `work/`**：`work/` 可重建且不進版控，但排程狀態遺失會讓所有來源被判定到期、全部重抓一輪。

```
{"sources": {"<source_id>": {
   "last_fetched": ISO8601,
   "next_due":     ISO8601,      # 依 sources.json 的 cadence 算出
   "last_changed": ISO8601,      # 內容真的變過的最後時間
   "pending_big": true|false,    # 有大檔被跳過還沒補抓；帶 --with-big 時會視為到期
   "files": {"<相對路徑>": {"sha256": ..., "bytes": ..., "fetched_at": ...}}
}}}
```

## archive/（歷史快照）

`archive/<source_id>/<YYYY-MM-DD>/<原路徑>`。只有 `sources.json` 裡 `archive: true` 的來源、而且 sha256 真的變了才會存；標 `big` 的大檔不存快照（版本資訊看 `state.json` 的 sha256）。

這些來源在官方端是覆蓋式更新、不留歷史（國健署年度名單、統計處各表、放名額公告、縣市年報），**沒存下來就永遠回不去**，所以排程的重點不是「抓到最新」，而是「把每一版留下來」。
