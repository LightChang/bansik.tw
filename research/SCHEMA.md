# 資料格式

`research/build/` 的輸出。資料層用 CSV（機器讀、git diff 可讀），行數 ≤1500 的表另外匯一份同名 `.md` 方便直接在 repo 翻。產生方式見 [`scripts/README.md`](scripts/README.md)。

| 檔案 | 列數 | 一列代表 |
|---|---|---|
| `entity.csv` | 3,075 | 一家機構（跨來源合併） |
| `entity_raw.csv` | 3,835 | 某個來源說的某家機構（保真） |
| `observation.csv` `.md` | 16 | 某時間點在某機構觀察到的一個值 |
| `relation.csv` | 14,476 | 一組關係（超過 1500 列，不匯 md） |
| `stats.csv` `.md` | 690 | 一個統計數值 |
| `materials.json` `.md` | — | 教育素材清單 |
| `manifest.json` | 72 | 一個原始檔的指紋 |

---

## entity.csv

| 欄位 | 說明 |
|---|---|
| `entity_key` | 有健保醫事機構代碼就用代碼（1,177 家）；社福單位退回 `x:<縣市>:<正規化名稱>` |
| `name` | 機構全銜，取來源優先序第一個 |
| `cat` | **主分類**，一家機構身兼多職時取優先序最前者 |
| `cats` | 全部分類，分號分隔，例如 `聯合評估中心;兒童發展篩檢院所;新生兒聽力確診醫院;療育-醫療單位` |
| `journey_step` | 家長旅程的第幾步：1 篩檢／2 通報／3 評估／4 療育／5 學前教育 |
| `county` `district` `address` `tel` | 地址已去掉開頭郵遞區號；`district` 只有就醫地圖來源有 |
| `hosp_id` | 健保醫事機構代碼 |
| `tier` | `重點`／`一般`，**只有國健署名單有**（89 家） |
| `lat` `lng` | WGS84，**只有就醫地圖有**（1,378 家） |
| `sources` | 這家機構出現在哪些來源，例如 `hpa;healthforkids;sfaa` |
| `source_updated` | 社家署那筆的更新日期（民國年） |

合併規則：欄位衝突時取 `hpa` > `healthforkids` > `sfaa`。理由是國健署是聯評中心的官方定義、就醫地圖有座標、社家署則是服務時間與服務區域的唯一來源。

主分類優先序：聯合評估中心 → 評估醫院 → 其他經許可辦理評估之醫院 → 兒童發展篩檢院所 → 新生兒聽力確診醫院 → 新生兒聽力篩檢院所 → 療育-醫療單位 → 早療機構 → 社區療育據點 → 通報轉介中心 → 個案管理中心 → 療育-教育單位 → 服務-教育單位 → 其他社福單位。

**所以 `cat` 的分類統計不等於各來源的原始筆數**：就醫地圖有 1,393 家篩檢院所，但其中 132 家同時是聯評中心或評估醫院，在 `entity.csv` 會歸到那些分類，`cat=兒童發展篩檢院所` 只剩 1,261 家。要按「有沒有提供某服務」篩選，請用 `cats` 欄位而不是 `cat`。

## entity_raw.csv

欄位是各來源的原始欄位：`entity_key, source, cat, county, district, name, 地址, 電話, hosp_id, tier, match, lat, lng, 服務區域, 服務方式, 服務內容, 辦理單位, 更新日期, note`。

- `match` 是怎麼對上代碼的：`name`／`addr`／`addr+hosp`／`substr`／`alias`／`none`／`skip`（社福單位一律不比對，同址常是別的機構）。
- `alias` 表示靠人工對照表補上的，目前兩筆更名案例在 [`scripts/aliases.json`](scripts/aliases.json)：陽明大學→陽明交通大學、臺大新竹分院→新竹臺大分院新竹醫院。
- **彰基刻意不合併**：彰化基督教醫院（1137010024）與彰化基督教兒童醫院（1137010042）在健保名冊是兩個機構、地址不同，聯評中心設在兒童醫院，社家署則把聯評身分掛在本院。合併會抹掉一個真實機構，所以保留兩筆——這也是 `entity.csv` 的聯合評估中心會比國健署 89 家多 1 家的原因。
- **同一個 `entity_key` 會有多列，而且可能同一個 `cat` 也重複**：來源本身就重複登錄。例如中山醫附醫在社家署有 5 筆，其中兩筆都是「聯合評估中心」但電話與更新日期不同。要追「某來源當時怎麼寫的」就查這張表。

## observation.csv

| 欄位 | 說明 |
|---|---|
| `entity_key` | 可直接 join `entity.csv`（目前 16 列全部對得回去） |
| `observed_at` | 觀察時間，取原始檔的抓取時間 |
| `source` | 哪個來源（`csh_quota`／`ntpc_booking`…） |
| `field` | `quota_release_date`（放名額日）／`monthly_capacity`（每月名額）／`booking_method`（預約方式） |
| `value` | 值。日期已轉成西元 `YYYY-MM-DD` |
| `note` | 原文脈絡，例如「115年10月份門診名額開放日」 |

**這張表很短是現況，不是解析失敗**：13 家聯評中心抽查只有 1 家公布放名額日。等候天數則沒有任何公開來源。

## relation.csv

`from_key, rel, to, to_key`。四種關係，同一組三元組已去重：

| `rel` | 列數 | 意義 |
|---|---|---|
| `in_county` | 3,075 | 機構所在縣市 |
| `in_district` | 1,378 | 機構所在行政區（只有就醫地圖來源有） |
| `serves_area` | 9,959 | **服務區域**，來自社家署欄位。必須當關係而不是屬性，因為通報轉介中心寫「全新北市」、有些療育單位收外縣市，只用地址縣市會漏 |
| `operated_by` | 64 | 辦理單位（例如社區據點由某醫院或基金會承辦）。`to_key` 是承辦單位的 entity_key，配不到就留空 |

## stats.csv

`metric, dim1, dim1_value, dim2, dim2_value, year, value, source`。兩層維度足以容納四種統計而不必 pivot：

| `metric` | 列數 | dim1 | dim2 | year |
|---|---|---|---|---|
| 早療通報人數 | 242 | 縣市 | — | 有 |
| 特教學生數 | 208 | 障礙類別 | 教育階段 | 無（來源未標學年度） |
| 兒少受虐人數 | 132 | 年齡層 | 性別 | 有 |
| 性侵害被害人數 | 108 | 身心障礙別 | — | 有 |

**取用注意**：性侵害那組含 `合計` 與 `非身心障礙` 兩列，直接加總會重複計算；要算身心障礙被害人請用 `合計 − 非身心障礙 − 不詳`。

## timeline.csv / timeline.md

年齡時間軸——幾個月大該做什麼。站的骨幹之一（另一半是地圖）。

`kind, journey_step, age_label, month_min, month_max, title, detail, source, url`，依 `month_min` 排序。

| `kind` | 筆數 | 內容 |
|---|---|---|
| 兒童預防保健 | 9 | 出生後2週至2個月 … 5歲至未滿7歲，健保給付含衛教指導 |
| 兒童發展篩檢 | 6 | 6至10個月、10個月至1歲半、1歲半至2歲、2至3歲、3至5歲、5歲至未滿7歲 |
| 家長紀錄事項 | 9 | 兒童健康手冊裡家長自填的九個時段 |
| 分齡篩檢量表 | 9 | 6-9個月 … 5-7歲，醫師篩檢實際使用的工具 |
| 線上發展檢核表 | 13 | 社家署 4個月～6歲，`detail` 標了題數與警訊題數 |
| 學前特教安置 | 4 | 幼幼班～大班 |

**兒童預防保健 9 次與兒童發展篩檢 6 次是兩套不同的東西**，都印在兒童健康手冊上、都用「就醫憑證」的形式，很容易混為一談。

月齡以月為單位，可能出現 `.5`：`0.5` 是出生後兩週，`84` 是未滿 7 歲。線上檢核表的區間原文寫成「3個月16天~5個月15天」，換算成 `3.5`–`5.5`——截成整數會讓相鄰兩層在邊界那個月重疊，查「5 個月大」會同時命中兩層。

學前特教安置的年齡是依學制推算的（來源只有班別沒有年齡），其餘都照原文。

## materials.json / materials.md

- `社家署線上兒童發展檢核表`：鍵是年齡層，值含 `items`（發展題數 11–13）、`alerts`（★警訊題數）、`sample`（首題原文）。md 版已按月齡排序。
- `社家署宣導資料`／`臺北市融合教育現場教學手冊`：`title` + `url` 陣列。
- `國健署兒童發展篩檢量表`：10 份 PDF 標題。
- `教育部性平網特教教學資源`：`total`（73）與 `special_ed`（57，已濾掉混在同一區的原住民族語繪本）。
- `CRPD繪本`：可直接下載的 `file` 或要再點進去的 `page`。

## manifest.json

`{generated_at, files:[{file, bytes, sha256, fetched_at}]}`，`file` 相對 `work/`。

## state.json（排程狀態）

放在 `research/state.json`，**刻意不放進 `work/`**：`work/` 可重建且不進版控，但排程狀態遺失會讓所有來源被判定到期、全部重抓一輪。

```
{"sources": {"<source_id>": {
   "last_fetched": ISO8601,
   "next_due":     ISO8601,      # 依 sources.json 的 cadence 算出
   "last_changed": ISO8601,      # 內容真的變過的最後時間
   "pending_big": true|false,    # 有大檔被跳過還沒補抓；帶 --with-big 時會視為到期
   "files": {"<相對路徑>": {"sha256": ..., "bytes": ..., "fetched_at": ...}}
}}}
```

## archive/（歷史快照）

`archive/<source_id>/<YYYY-MM-DD>/<原路徑>`。只有 `sources.json` 裡 `archive: true` 的來源、而且 sha256 真的變了才會存；標 `big` 的大檔不存快照（版本資訊看 `state.json` 的 sha256）。

這些來源在官方端是覆蓋式更新、不留歷史（國健署年度名單、統計處各表、放名額公告、縣市年報），**沒存下來就永遠回不去**，所以排程的重點不是「抓到最新」，而是「把每一版留下來」。
